# AI 小说 & 短剧创作工作台 —— 项目路演材料

---

## 一、一句话定位

**一个面向内容创作团队的 AI 原生工作台，将"小说创作 → 短剧改编"的完整工作流从分散的本地脚本升级为可协作、可追踪、可导出的云端产品。**

---

## 二、我们解决什么痛点

### 市场背景

2024-2025 年，短剧市场爆发式增长，但行业存在一个结构性矛盾：

- **上游**：大量网文 IP 等待改编，但改编过程依赖编剧个人经验，效率低、成本高
- **中游**：AI 辅助写作工具很多，但都是单点工具（写作助手、剧本生成器），没有打通"小说 → 短剧"的完整链路
- **下游**：创作团队（2-4 人）需要协作，但现有方案要么是单机脚本，要么是面向大企业的复杂 CMS

### 用户痛点

| 痛点 | 现有方案 | 我们的方案 |
|------|---------|-----------|
| 小说生成和短剧改编在两个工具里做 | 用本地 Python 脚本跑小说，再手动复制到另一个工具生成剧本 | 一个平台完成：架构 → 目录 → 章节 → 改编计划 → 分镜脚本 |
| AI 生成长文本前后不一致 | GPT 写第 1 章和第 10 章可能把角色写死又写活 | 结构化世界状态追踪，自动提取角色/事件/设定变更 |
| 多人协作靠微信传文件 | 文件版本混乱，谁改了什么不知道 | 项目级云端协作，任务状态实时可见 |
| 短剧剧本格式不专业 | 生成的文本不是分镜格式，导演看不懂 | 直接生成导演分镜脚本（场景/镜头/台词/运镜/音效） |
| 每个人 API Key 管理混乱 | 团队成员共用平台 Key，费用不清 | 支持个人 API Key 加密存储，按人计费 |

## 三、产品核心能力

### 3.1 完整工作流（已跑通）

```
创建项目
    ↓
AI 生成小说架构（世界观、人物、主线）
    ↓
AI 生成章节目录
    ↓
逐章/批量生成正文
    ↓
人工编辑与定稿
    ↓
AI 生成短剧改编计划（集数、节奏、钩子）
    ↓
逐集生成分镜头脚本
    ↓
导出 JSON / Markdown / CSV
```

### 3.2 六大差异化能力

#### ① 结构化世界状态记忆

**行业首创**：长文本生成的核心难题是"前后一致性"。我们设计了 Genre-aware 的世界状态追踪系统：

- **Genre Templates**：自动匹配小说类型（修仙/都市/玄幻），提取不同维度的追踪项
- **Delta Extraction**：每章生成后，AI 自动提取角色状态、事件进展、世界设定变更
- **State Summary**：生成下一章时，自动筛选最相关的 5-10 条状态注入 Prompt
- **Change History**：可视化展示每一章导致的状态变更（谁在什么时候获得了什么能力、什么物品损坏）

> 效果：彻底解决了"前面写死的角色后面又出场"、"境界倒退"等 AI 长篇写作的经典问题。

#### ② 角色状态自动演化

- 每章生成后，AI 自动更新角色状态文档（能力、物品、关系、心境）
- 下一章生成时，角色状态自动注入 Prompt
- 支持一致性检查，发现冲突自动告警

#### ③ 导演级分镜脚本生成

短剧脚本不是简单的小说摘要，而是直接可用的导演分镜：

```json
{
  "scenes": [
    {
      "scene_num": 1,
      "shots": [
        {
          "shot_num": 1,
          "type": "广角",
          "duration": "3s",
          "visual": "深夜，废弃工厂外",
          "action": "主角从阴影中走出",
          "dialogue": { "speaker": "主角", "content": "我等了三年..." },
          "camera_movement": "缓慢推进",
          "audio": "风声，远处警笛"
        }
      ]
    }
  ]
}
```

支持续集记忆：生成第 N 集时自动注入前 N-1 集的关键道具和结尾台词，保持连续剧逻辑连贯。

#### ④ 个人 LLM 配置（BYOK）

- 每个用户可配置自己的 LLM API Key（OpenAI / 国内模型均可）
- Key 使用 Fernet 加密存储，平台无法读取
- 团队共用平台时，费用按人分开，不互相干扰
- 平台仅提供兜底配置（无个人 Key 时使用）

#### ⑤ 异步任务队列 + 实时进度

AI 生成单章需 30 秒-5 分钟，短剧脚本需 2-5 分钟。我们采用 Celery + Redis 的异步架构：

- 用户点击"生成"后立即返回任务 ID
- 前端轮询进度（0% → 20% → 40% → ... → 100%）
- 任务崩溃自动恢复（启动时扫描僵尸任务并标记失败）
- 支持任务取消和重试

#### ⑥ 多格式导出

- **小说**：单章导出、批量导出（Markdown / JSON）
- **短剧脚本**：JSON（结构化数据）、Markdown（阅读版）、CSV（统计版）
- **整项目**：一键导出完整项目 Markdown 文件

## 四、技术架构

### 4.1 技术选型（现代、主流、可扩展）

| 层级 | 技术 | 选型理由 |
|------|------|---------|
| **前端** | React 18 + TypeScript + Tailwind CSS + React Query + Zustand | 工业标准，类型安全，状态管理清晰 |
| **后端** | FastAPI + SQLAlchemy 2.0 + Alembic | Python 生态最强异步 Web 框架，自动生成 OpenAPI 文档 |
| **数据库** | PostgreSQL 16 | 支持 JSONB、全文搜索，扩展性强 |
| **缓存/队列** | Redis 7 + Celery 5.4 | 成熟稳定，支持任务重试、超时控制 |
| **向量存储** | Chroma（本地）/ 可迁移 Qdrant | 轻量启动，未来可无缝迁移到云向量库 |
| **部署** | Docker + Render + Vercel | 一键部署，成本可控 |

### 4.2 架构亮点

#### 分层清晰（六层架构）

```
Router 层（API 入口）
    ↓
Service 层（业务逻辑）
    ↓
Infra 层（数据库/Redis/向量库）
    ↓
Core 层（配置/安全/常量）
```

- Router 不写业务逻辑，Service 不写 HTTP 逻辑
- 单元测试覆盖核心模块（已覆盖世界状态合并、JSON 解析等 21 个用例）

#### 异步任务引擎

```
用户请求 → 创建任务记录 → 推入 Redis → 返回 task_id
                                    ↓
                            Celery Worker 消费
                                    ↓
                            执行 LLM 调用（30s-5min）
                                    ↓
                            写入数据库 → 更新任务状态
```

- 单容器内通过 Supervisor 同时运行 FastAPI + Worker，资源利用率高
- 未来可横向扩展 Worker 数量，支撑更多并发

#### 安全设计

- JWT Token 认证（24h 过期）
- bcrypt 密码哈希
- API Key 加密存储（Fernet AES-128）
- 项目级数据隔离（所有查询带 owner_id 过滤）
- CORS 域名白名单

## 六、市场与商业模式

### 6.1 目标市场

- **核心用户**：2-4 人短剧编剧团队、网文工作室、MCN 内容部门
- **市场规模**：2024 年中国短剧市场规模 500 亿+，编剧外包需求旺盛
- **竞品分析**：
  - 阅文作家助手：仅小说写作，无短剧改编
  - 海马轻帆：剧本分析工具，无 AI 生成
  - 各种 GPT 套壳：单点工具，无工作流

**我们是唯一打通"小说生成 + 短剧改编"双工作流的产品。**

### 6.2 商业模式

**阶段一（当前）：免费内测**
- 用户自带 API Key（BYOK），平台零算力成本
- 积累种子用户，打磨产品

**阶段二：SaaS 订阅**
- 个人版：¥29/月（基础生成额度）
- 团队版：¥99/月（3 人协作 + 优先队列 + 高级导出）
- 企业版：定制（私有部署 + 模型定制）

**阶段三：生态**
- 接入更多模型（Claude、Gemini、国产大模型）
- 剧本交易平台（连接编剧和制片方）
- IP 评估工具（预测小说改编潜力）
