## Phase 1：MVP —— 单人闭环

**目标**：一个用户可以完成从项目创建 → 小说生成 → 短剧改编 → 导出的完整闭环。

**周期**：预计 4-6 周

### 1.1 必须完成

| 模块 | 功能点 | 优先级 |
|------|--------|--------|
| **脚手架** | FastAPI 项目结构（core/infra/models/schemas/routers/services） | P0 |
| **脚手架** | React 项目结构（api/components/pages/hooks/store/types） | P0 |
| **脚手架** | docker-compose.yml（PG + Redis + Backend） | P0 |
| **认证** | 用户注册、登录、JWT、当前用户信息 | P0 |
| **项目** | 项目 CRUD、列表、详情 | P0 |
| **LLM 配置** | API 配置读取、多模型支持（复用 adapter） | P0 |
| **小说生成** | Step1: 生成架构（异步任务） | P0 |
| **小说生成** | Step2: 生成目录（异步任务） | P0 |
| **小说生成** | Step3: 生成单章（异步任务） | P0 |
| **小说生成** | Step4: 章节定稿（异步任务） | P0 |
| **内容编辑** | 架构编辑、目录编辑、章节编辑 | P0 |
| **资产管理** | project_assets 表读写 | P0 |
| **任务系统** | 任务创建、状态查询、进度追踪 | P0 |
| **短剧改编** | 生成改编计划 | P0 |
| **短剧改编** | 生成单集脚本 | P0 |
| **短剧改编** | 分镜预览 | P0 |
| **导出** | JSON / Markdown / CSV 导出 | P0 |
| **前端页面** | 登录页、项目列表、项目工作台（6个 Tab） | P0 |
| **部署** | 本地 docker-compose 可完整运行 | P0 |
| **部署** | 云端部署跑通（Railway + Vercel） | P0 |

### 1.2 明确不做

以下功能在 Phase 1 中**绝不开发**：

- 团队协作（成员邀请、权限控制）
- 编辑锁 / 乐观锁
- 项目快照与版本恢复
- WebSocket 实时推送
- 一致性检查 Agent
- 结构化记忆可视化
- 语义搜索 / 全文搜索
- 批量生成（单章生成为主，批量可后续扩展）
- 角色库管理
- 复杂 API 配置中心（基础配置够用）

### 1.3 验收标准

Phase 1 完成时必须满足 PRD 第 15 条的 10 项成功标准：

1. 用户可以登录
2. 用户可以创建项目
3. 用户可以生成小说架构
4. 用户可以生成目录
5. 用户可以生成至少一章正文
6. 用户可以编辑并保存章节
7. 用户可以生成短剧改编计划
8. 用户可以生成至少一集短剧脚本
9. 用户可以导出脚本
10. 项目可以在云端成功部署并访问

## Phase 2：小团队协作

**目标**：支持 2-4 人团队协同使用。

**前提**：Phase 1 MVP 已跑通，用户反馈验证核心流程有价值。

### 2.1 功能清单

- [ ] 项目成员邀请（邮箱邀请链接）
- [ ] 角色权限（admin / editor / viewer）
- [ ] 编辑锁：章节编辑时锁定，防止冲突
- [ ] 乐观锁：数据库 version 字段，冲突时提示合并
- [ ] 项目快照：手动创建快照，支持回滚到历史版本
- [ ] API 配置中心：团队共用模型配置
- [ ] 更丰富的任务日志：任务执行时间、Token 消耗、费用估算
- [ ] 批量生成：一键生成全部章节

### 2.2 技术要点

- 数据权限：所有查询增加 `project_id` + `user_id` 校验
- 编辑冲突：优先实现编辑锁（简单），后续考虑乐观锁
- 快照：基于 project_assets + chapters 的完整备份表

---

## Phase 3：增强智能

**目标**：提高内容质量与系统可维护性。

**前提**：Phase 2 协作功能稳定，有持续使用用户。

### 3.1 功能清单

- [ ] 一致性检查 Agent（复用 consistency_checker.py）
- [ ] 全文搜索（PostgreSQL full-text search）
- [ ] 语义搜索（Chroma / Qdrant 向量检索增强）
- [ ] 结构化记忆可视化（时间线、角色状态面板）
- [ ] 更强的导出（EPUB、Word、剧本行业标准格式）
- [ ] 高级任务编排（批量生成 + 断点续传）
- [ ] WebSocket 实时推送（任务完成通知）
- [ ] 操作日志与审计

### 3.2 技术要点

- 向量存储迁移评估：Chroma 单实例是否够用 → Qdrant 云服务
- WebSocket 引入：仅用于任务通知，不用于协同编辑
- 一致性检查：作为独立异步任务，不阻塞生成流程

## 决策冻结项

以下决策在 Phase 1 期间冻结，不讨论变更：

- 后端框架：FastAPI
- 数据库：PostgreSQL
- 前端：React + TypeScript
- 架构：前后端分离
- 异步模型：任务队列 + 轮询
- 部署：Vercel + Railway/Render
- 向量库：Chroma（本地持久化）
