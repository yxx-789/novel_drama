# V3 生成系统设计（积木式配置 + 创作意图 + 减法 prompt + 记忆优化）

- 日期：2026-08-05
- 状态：设计草案（待审）
- 目标项目：`/Users/yxx/Desktop/novel_drama_v2`

## 背景与问题

当前生成系统存在系统性缺陷：
1. **题材/风格形同虚设**：genre 只在核心种子里传一个字符串 + 一句空泛的"文风需与小说类型匹配"，所有题材共用一套泛化写作指令 → **千篇一律**
2. **硬编码结构假设**：prompt 强制"3-6 个核心角色"、"三幕式危机"、"认知颠覆"、"悬念钩子结尾" —— 群像文/种田文/甜宠/日常等题材全被套进热血悬念模型
3. **受众不区分**：低门槛爽文受众（要短句快节奏高密度爽点）和高品质受众（要文笔逻辑）用同一套写法
4. **记忆机制不足**：前章"概要"是计划 outline 非实际内容、前章窗口只有 1500 字、角色状态无限膨胀

目标：把生成系统改造成**积木式配置系统**——用户粗选、内部细配、意图高优先、风格多样、受众适配。

## 总架构

```
┌─ 用户层（创建项目时，正交粗维度）─────────────────────┐
│ ① 核心题材  ② 背景设定  ③ 核心卖点  ④ 叙事结构        │
│ ⑤ 文风格调  ⑥ 受众档位  ⑦ 角色规模                    │
│  + 主题 + 剧情走向（创作意图，最高优先）                │
│  + 自定义设定（卖点/独特设定/人物/避雷/自由补充）        │
└────────────────────────────────────────────────────┘
              ↓ 后台组装
┌─ 内部层（细粒度风味库，用户不可见，自动配）───────────┐
│ 每个粗维度挂一组子风味块，随机选 1 或组合 2-3 个        │
│ （每个项目选一次，存 writing_config，可"重新掷风味"）  │
└────────────────────────────────────────────────────┘
              ↓
         写作上下文 = 创作意图 + 粗维度积木 + 内部风味
              ↓ 注入生成（减法 prompt：参考非规则）
         架构 → 目录 → 章节（含记忆：真实摘要/角色瘦身/分层记忆）
```

## 一、用户层：7 个正交粗维度

| 维度 | 互斥选项 | 说明 |
|------|---------|------|
| **① 核心题材**（单选） | 玄幻/仙侠/都市/科幻/奇幻/历史/悬疑/言情/武侠/灵异/军事/体育 | 宽泛根题材 |
| **② 背景设定**（多选） | 现代/古代/民国/星际/末世/异世界/赛博朋克/洪荒/西游/四合院/兽世 | 时空/世界背景 |
| **③ 核心卖点**（多选） | 金手指/系统流/重生/穿越/赘婿/打脸/无敌流/神豪/万人迷/追妻火葬场/囤货/娇软/女强/病娇 | 钩子/套路标签 |
| **④ 叙事结构**（单选） | 主线成长/无限流/快穿/群像/单元剧/种田日常 | 章节组织 |
| **⑤ 文风格调**（单选） | 热血/细腻/冷峻/治愈/诙谐/暗黑/轻快 | 笔触语调 |
| **⑥ 受众档位**（单选） | 轻松爽文/标准/精品 | 句长/爽点/逻辑权重 |
| **⑦ 角色规模**（单选） | 精简(3-5)/标准(6-10)/群像(15+) | 角色数量 |

- 默认配方：每个核心题材预置合理组合（选"言情"→自动配 细腻文风+标准受众+精简角色），用户可改
- 组合爆炸：12 题材 × 多背景 × 多卖点 × 6 结构 × 7 文风 × 3 受众 × 3 规模，理论数千种

## 二、内部层：细粒度风味库（自动配）

每个粗维度挂一组子风味块（长尾覆盖），用户不可见，生成时随机选 1 或组合 2-3 个：

| 用户选 | 内部子风味库（节选） |
|--------|---------------------|
| 玄幻 | 洪荒/西游衍生/诸天万界/克苏鲁味/巫师/高武/盗墓 |
| 都市 | 四合院/港岛/神豪/医仙/兵王/鉴宝/赶海/美食 |
| 言情 | 追妻火葬场/万人迷/病娇/先孕后爱/女强/娇软 |
| 悬疑 | 密室/本格/灵异/无限流副本/刑侦 |
| 文风·细腻 | 细腻抒情/轻小说感/文艺腔/冷幽默 |

- **每个项目选一次**（存 writing_config），保证全书风味一致
- 提供「重新掷风味」按钮换一批
- 用户给了明确主题/剧情走向时，**内部风味服从创作意图**（只作补充不越权）

## 三、创作意图（最高优先级）

**新增字段**：`剧情走向`（用户可填一段愿景：走向、结局倾向、关键情节）

**注入方式**：作为独立的【创作意图（用户硬性要求）】块，注入所有生成环节（架构/目录/章节），prompt 明确写：
> 以下是用户的创作意图，**必须严格遵循，不得偏离或擅自改写**。若与其它设定冲突，以此为准。

**优先级**（高→低）：
```
用户创作意图（主题+剧情走向）＞ 自定义设定字段 ＞ 题材默认配方 ＞ 内部风味 ＞ 积木通用默认
```

**体验感目标**：用户给越具体，生成越贴合，感受到"我的输入被听进去了"。

## 四、自定义设定（套入模板 + 自由兜底）

| 字段 | 套入位置 |
|------|---------|
| 核心卖点（一句话看点） | 核心种子 + 目录 |
| 独特设定（金手指/系统规则/世界观） | 世界设定 + 架构 |
| 人物要求（主角/配角/禁忌） | 角色设计 |
| 避雷（不要出现什么） | 章节草稿【避雷】区 |
| 自由补充（任意其他） | 【作者补充要求】区（通用兜底） |

（可选进阶：LLM 把用户一句话描述自动解析成配方——后置）

## 五、减法 prompt（参考非规则）

**删除的硬规则**（千篇一律元凶）：
- "必须包含显性冲突与潜在危机"、"至少 1 个认知颠覆时刻"、"不要写总结性结尾，要在悬念最高点收束"、"每 3-5 章一个悬念单元"、"设计 3-6 个核心角色"

**保留的轻骨架**（任何题材都适用）：
- 呼应前文、章节有起落、围绕创作意图推进

**积木→prompt 片段**：每个积木块对应一段 prompt 片段（文风块→语调段、受众块→句长/爽点段、结构块→叙事骨架段、伏笔块→埋设手法段），组装成一个「写作上下文」注入生成，措辞为"本题材通常…你可以…"（参考，非必须）。

## 六、受众适配（受众档位块）

| 档位 | 句长 | 爽点密度 | 逻辑权重 | 铺陈容忍 |
|------|------|---------|---------|---------|
| 轻松爽文 | 短句直白 | 高（3章小爽/10章大爽） | 低 | 低 |
| 标准 | 中 | 中 | 中 | 中 |
| 精品 | 可复杂讲究 | 低但钩子密 | 高 | 高 |

受众块派生：句长要求、爽点节奏、AI 味避雷侧重（如精品档禁疲劳词）。

## 七、记忆优化（V3 的一部分）

1. **真实章节摘要**：每章生成后用 LLM 生成"实际发生了什么"摘要，存下来替代计划 outline 作为前情
2. **动态前章窗口**：按比例取前章结尾（而非固定 1500 字）
3. **角色状态瘦身**：只保留活跃角色 + 近 N 章变化（学 world_state 摘要机制）
4. **分层摘要（后置）**：章节摘要 → 分卷摘要 → 全局圣经，按层取用
